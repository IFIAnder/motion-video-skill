# 差距分诊：Flash 级模型 vs Opus 级模型，在动画/视频上差在哪、能补什么

这份文档是给"想用便宜模型干贵活"的人看的。诚实分类，别自我安慰。

## 一、差距拆成四层

| 层 | 具体表现 | 小模型 | 强模型 | 能不能补 |
| --- | --- | --- | --- | --- |
| **中间态** | 只写首末帧，中间靠浏览器补；缓动是假的 | 高频 | 少 | ✅ 结构上能根治（见下） |
| **长代码一致性** | 400 行场景里单位/坐标系/变量名错一处，整段崩 | 高频 | 偶尔 | ✅ 靠拆分 + 机器验收 |
| **隐式审美** | 留白、层级、配色、节奏、缓动曲线的默认值 | 平庸 | 好 | ⚠️ 部分（靠参考 + 约束表） |
| **全局连贯** | 30 秒里镜头之间的关系、母题、节奏起伏 | 散 | 稳 | ❌ 需要人拆镜 + 参考片 |
| **角色/物理** | 人物表演、布料、流体、真实运镜 | 不会 | 也不会 | ❌ 换工具，不是换模型 |

前两层占了实际交付失败原因的 **七成以上**，而且都是**可以用工程手段根治的**。
真正补不平的是后两层——但那两层本来也不是"写代码"能解决的。

## 二、三个真正有效的手段

### 1. 规格化：把审美判断提前变成数值

让模型直接"做一个好看的片头"，它会在没有约束的空间里随机游走，产出 2010 年 PPT 风。

改成先填表：

```
入场时长 0.6s，曲线 easeOutCubic，位移 y 从 96 到 0，字间错开 75ms
```

这不再是审美问题，是代入公式。小模型在**有唯一正确答案**的任务上，损失最小。
代价是你（或 skill）得先想清楚这张表——这本来就是人该干的事。

**关键**：表里每个元素必须有 `enter` / `active` / `exit`。只写 enter 的元素，
在代码里就只剩入场函数，这就是"中间态丢失"的根因。

### 2. 纯函数渲染：用结构强迫它想中间帧

```js
seek(t) { ... }   // 画面完全由 t 决定
```

一旦画面必须由 `t` 决定，`t` 就是**每一帧都要被求值**的东西。
这时"中段 1.0–2.0s 什么都没发生"不再是一个隐蔽的疏忽，而是一个
**会被像素检测抓到的、必须解释的事实**。

对比 CSS `@keyframes`：浏览器帮你插值，模型只写两端，中间是黑盒。
一旦有东西错了，它没有任何手段定位。`seek(t)` 把黑盒变成白盒。

### 3. 机器验收：给它补上"眼睛"

`audit.mjs` 会告诉它：没动 / 中段静止 1.1–2.5s / 在 2.3s 硬跳 / 17 帧纯色 / 首末帧不一致。
这些是**断言级**的反馈，不是"感觉不太好"。模型看到"中段 1.10–2.57s 静止"，
下一步自然去补那一段的插值——这就是一次自我修正。

小模型的真实劣势不是"改不对"，而是"不知道要改"。
回环把"不知道"变成"知道"，这一步的效果大于任何 prompt 修饰。

## 三、补不平的部分，具体是什么

别指望 skill 解决这些：

- **创意构图**：三分法、负空间、视觉引导线、隐喻。强模型的默认审美来自训练分布，
  小模型给同样的规格表，摆出来的版面就是更僵。**解法：给参考图/参考片，让它照着复刻布局**，
  而不是让它原创构图。
- **长片全局节奏**：30 秒以上的片子需要母题、留白呼吸点、情绪曲线。
  **解法：人写镜头表，模型只负责把每个镜头实现干净**——这恰好也是工业流程。
- **角色动画**：~~走路、口型、表情。解法：Lottie/Rive 现成资产，或直接换视频模型。~~
  **修正：这条能补。** 风格化 2D 角色 = 部件 PNG + 父子变换链 + pose 数据，
  只要 Canvas 就够，见 [rig-characters.md](rig-characters.md)。补不平的是**写实人体**
  （骨骼解剖、肌肉滑动、连续软体变形）——那确实要 3D。
- **运动模糊与电影感**：不是能力问题是流程问题，`--motion-blur 180` 就解决。见
  [cinema-grade.md](cinema-grade.md)。**这条最容易被低估**：同样的曲线，有快门和没快门
  是两个观感档次。
- **物理真实**：弹簧、碰撞、流体。**解法：用现成的物理库，或降级成"风格化运动"。**

## 四、什么时候该换模型

用这个判据，别用"重要不重要"：

| 条件 | 结论 |
| --- | --- |
| 产物是**代码**，可被机器验收，错了能改 | 小模型 + 本 skill，够用 |
| 产物是**一次性的审美判断**，改不动（比如品牌片定稿） | 上强模型 |
| 需要**在无参考的情况下原创构图** | 上强模型，或先找人给参考 |
| 时长 > 1 分钟且镜头之间需要呼应 | 人拆镜 + 小模型实现每镜 |
| 需要真实感画面 | 换视频生成模型，跟这里的模型选择无关 |

## 五、反过来：同样的 skill 给强模型会怎样

会更强，但不是"翻倍"。因为：

- 强模型本来就很少丢中间态 → 本 skill 的第一层收益对它几乎为零
- 强模型的隐式审美本来就在 → 规格表对它是**约束**，可能反而压住它

所以本 skill 的定位很清楚：**把弱模型的短板补到"交付线以上"，
而不是把任何模型推到"大师级"**。

一句实话：用 Flash 1017 做动画，配上这套东西，产出能到
"专业外包的及格线、内部演示的良"；到不了"能上戛纳"。
但"不及格"和"及格"之间的差距，比"及格"和"大师"之间的差距，对你更值钱。

## 六、还有一种差距：用不用工具

这一条容易被忽略，但实测影响很大。

Flash 级模型有个稳定的偏好：**它能自己算的，就不调工具**。它把"省一次调用"当成省钱，
于是自己估贝塞尔控制点、自己估 7 个元素的错开步长。问题在于这类错的**失败信号极弱**：

- 曲线参数偏一点：动画照样播，只是不丝滑。没有人会指着它说"你这里错了"
- 步长偏一点：所有元素糊在一起，观感"土"，但说不出为什么
- 对比度估错：字在那儿，只是看着累

强模型不一定每次都算对，但它更愿意先确认再写。这一条差距**能用工程手段几乎完全抹平**，
因为它根本不是能力问题，是决策问题——只要把"要不要用工具"变成"流程里有没有这一步"。

做法（本 skill 已内置）：

1. 把工具调用做成**流程节点**（STEP 1 填曲线列必须来自 `ease.mjs` 输出）
2. 给它**正确的成本函数**（见 SKILL.md 里的对照表：心算期望 19 秒 vs 调工具 0.5 秒）
3. 把它的"想再确认一下"引导到 `verify.mjs`，而不是让它自己在脑子里模拟
4. 交付自检写成可判定的：**回答里每个数字都要能指向上一条命令的输出**

一句总结：**能力差距靠回环补，意愿差距靠流程补。** 后者更便宜，见效更快。

## 七、"敢不敢"：没有元素时自己用代码画

这一条比参数精度更致命，因为它直接决定画面的**信息密度上限**。

渲染管线只有 HTML/CSS/SVG/Canvas。这意味着**画面上每一个像素都必须是代码产生的**。
于是"敢不敢自己画"就等于"画面能有多丰富"。强模型和弱模型在这里的行为分离得很干净：

| | 强模型 | 弱模型 |
| --- | --- | --- |
| 需要光效 | 写 `radial-gradient` + `mix-blend-mode: screen` | 不加，或加一个生硬的 `box-shadow` |
| 需要纹理 | 内联 `feTurbulence` data-uri | 不加，画面"太干净所以廉价" |
| 需要插画 | 手写 SVG `path`，几层叠出景深 | 画一个圆角矩形，或留白 |
| 需要图标 | 内联 SVG path 集 | 用 emoji（跨平台渲染还不一致） |
| 缺一块内容 | 用代码造一个视觉元素填上 | 「这里建议插入一张图片」 |

最后一行是关键：**它会把活推回给你**。这不是能力问题，是风险偏好——它怕画错，
所以选择不画。结果就是"只有文字 + 纯色背景"的产物，这种产量在实测里占绝大多数。

### 补法：给它弹药，而不是打气

说"你要大胆一点"没有任何效果。有效的做法是**把"敢画"变成"抄"**：

1. `references/asset-recipes.md` 提供 20 类可直接粘贴的片段（光晕、扫光、颗粒、玻璃卡、
   霓虹、网格、抽象插画、粒子、线框球、图表、城市剪影、故障风、扫描线、图标集、光束、
   景深、布纹、散景、伪 3D）。它不需要"敢"，只需要复制并改数值。
2. 铁律写成可判定的：**每个画面至少三层、至少 2 个自建视觉元素、1 处深度线索**。
   只有一层 = 不合格，直接重做。
3. 明令禁止退缩动作：「建议插入图片」「等素材」「用 emoji 当图标」全部不许出现。
4. `render --guides` 叠加安全区和三分线，让它能自己看出"标题压过边了"——
   构图判断里能被机器辅助的部分，就不要靠它的审美。

### 一个实测

按这套规则生成的 `examples/illustrated-scene.html`：3 秒 1080p，画面里的
背景聚光、网格、三层远山、240 个星点、11 个散景、线框球、玻璃卡、图标、数字滚动、
进度环、扫光、胶片颗粒 **全部是代码**，没有任何外部素材。audit `PASS`，
变化像素均值 1.40%（对标"标题进场"那版 demo 的 0.58%）——信息密度直接翻倍。

结论：这条差距**补得动**，而且补起来最便宜——不需要更好的模型，只需要一份片段库
加一条"不许等素材"的硬规则。

## 八、看过一个真实的 Opus 作品集级产物之后（校准）

拿一个 60 秒 / 60fps / 角色骨骼 / 音频同步的作品集短片反推，它强在五个地方，
其中四个是**工程结构**，只有一个是模型能力：

| 它做了什么 | 属于 | 能不能补 |
| --- | --- | --- |
| **元叙事**：用动效讲动效 —— 第一章演示缓动曲线，第三章拆解自己的角色骨骼（雷达扫描逐个点亮 24 个部件），第五章用字幕列 12 条原则并让角色逐条演示 | 选题与结构 | ⚠️ 部分是品味，但"用自身能力当主题"这个套路可以教 |
| **贯穿全片的 HUD**：时间码 `TC 00:00:07:13`、帧号 `F 0130/3600`、`1920×1080 · 60FPS · 180° SHUTTER`、章节号滚动、进度条、REC 闪烁、四角裁切标记 | 工程 | ✅ 已进 [cinema-grade.md](cinema-grade.md) §4 |
| **运动模糊**：按"该帧是否在快速运动"自适应 6/8/12/24 个子采样，`globalAlpha = 1/(i+1)` 累积平均 | 工程 | ✅ `--motion-blur 180` |
| **时间轴常量表**：`cues.js` 一个文件，视觉与配乐共用；120BPM、1 bar = 2s；弹跳用 `G=30000` 卡通重力推导飞行时间；雷达扫描用二分反解每个部件被扫到的时刻 | 工程 | ✅ 已进 [code-patterns.md](code-patterns.md) §1.5 |
| **角色骨骼**：部件 PNG + `DOMMatrix` 父子链 + pose 偏移表，24 个部件，三种姿态（T-POSE / HERO / SHRUG） | 工程 | ✅ 已进 [rig-characters.md](rig-characters.md) |

反过来，它踩过而我们知道怎么免掉的坑：**骨骼枢轴点错位**（"绕手腕转"）、
**部件 z 序错**（后发盖住脸）、**编码暗部色带**（靠 `noise=c0s=5` 的抖动压掉）。

### 所以差距的真实构成

- **七成是工程结构**：HUD、常量表、快门、骨骼、编码参数、并行渲染。这些**照抄就行**，
  文档已经都在这个 skill 里了。
- **两成是执行精度**：曲线选得准、节奏卡在拍点上、错开步长不糊。`ease.mjs` +
  `verify.mjs` + `audit` 三层回环专门治这个。
- **一成是品味**：选题、构图、母题选择。这一成补不动，但可以被"参考 + 复刻"绕过，
  也可以被"用能力当主题"这个套路掩盖——作品集里最安全的自选题就是"我很会动"。

**结论**：Flash 级模型 + 这套东西，能做到同一套结构，
差距从"观感档次差两级"缩到"执行细节差一档"。

## 九、为什么一段话的 prompt 就能出大作

这里有个反直觉的事实：那个 60 秒片子的原始 prompt 只有一段话，没有尺寸、没有章节、
没有配色、没有曲线。它照样成立了，因为那一句话里**四个槽位都满了**：

| 槽位 | 原话 | 缺了会怎样 |
| --- | --- | --- |
| 母题 | 「人物素材已经在工作空间中」 | 变成抽象图形堆砌，没有主角 |
| 元叙事 | 「展示你是一位多么出色的动效设计师」 | 变成一个孤立动效，做完就完了 |
| 形式 | 「就像作品集短片那样」 | 变成"一个大动效"而非"有章节的片子" |
| 档位 | 「全力以赴」 | 保守、处处收着 |

**元叙事是最高杠杆那项。**"证明我很会动效"会自动展开成章节：缓动曲线、字体运动、
角色动作、12 原则、风格变体、循环、收尾——一份 storyboard 的骨架就出来了。

**母题是第二重要的。**"素材在工作空间里"把任务从"凭空想象"改成"围绕既有素材组织"。
前者是弱模型最弱的地方（原创构图必然平庸），后者是它最擅长的（受约束转录）。
这就是为什么许愿模式下**第一步不是设计，是扫目录**。

所以"许愿式创作"不是"省掉规格"，而是**把写规格的责任从用户转到模型**。
责任转移了，工序不能省——许愿模式的纪律要更严，因为没人给你兜底。

详见 [wish-mode.md](wish-mode.md)。四条结论：

1. 四槽位缺哪个，自己补哪个，**不许反问**
2. 先扫工作空间找母题（角色/logo/字体/音频/既有代码）
3. 元叙事 → 章节 → 每章一个可演示点，宁少勿滥（大杂烩是头号失败形态）
4. 把"确认"从用户身上转到 `verify`/`audit`/`--still` 身上
